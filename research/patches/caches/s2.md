## What it does

`BufferCache::ObtainBuffer` used to copy every small read-only range (`!is_written`, `size <= STREAM_THRESHOLD`, 16
KiB, not GPU-modified) into the stream buffer on every use. With S2 a range the CPU has not written since its
last upload (`!IsRegionCpuModified`) is bound from the arena: no copy, no upload, no render pass break. A
CPU-written range is promoted once: it is uploaded into the arena by `SynchronizeMemory`, only while no render pass
is open (`!scheduler.IsRendering()`). If it is found CPU-written again after that, it is marked dynamic and keeps the
stream copy (state in the stream-class table).

## Invariants

- Correctness rests on the page tracker. Before the next `ObtainBuffer`, every CPU write must either mark the
  range CPU-modified (a write fault on a protected page) or reach the arena itself (D2's queued precise writes,
  `ProcessCpuWritesLocked`). The old stream copy re-read guest memory on every use and hid any missed write. With
  S2 a missed write binds stale bytes (class C).
- A promotion (state 0 -> 1) happens only when `!scheduler.IsRendering()`. Otherwise the range takes the stream
  copy. Promoting inside a pass would end it.
- GPU-modified and written (`is_written`) ranges never take this path. `small_gpu_modified` is computed once and
  used by both branches.
- The switch is read live on every call from `Gow3Settings::Get().perf[PerfSmallBuffers]`. At start
  `gow3_settings.cpp` sets it only when `GOW3_STREAM_CLEAN` is `1`. `run.py` sets that for MediEvil
  (`setdefault`), `perf_small_buffers=0` makes it `0`, and other games start with S2 off.

## Interactions

- The stream-class table holds the 0/1/2 state. Its replacement (de30a39) removed the 8-12 ms panning hitch that
  the old `unordered_map` clear caused here.
- Arena bindings go through `GetArena` / `EnsureResident` / `SynchronizeMemory`. S2 therefore adds residency checks
  (R2-residency-bitmap answers them) and, with U2 mapped, `NoteArenaUse` walks.
- Promoted uploads outside a pass add write protection to those pages. A range the CPU rewrites often costs one
  write fault, then stays dynamic.
- It came in with the hzb-remap defaults commit (`57dc5c4`), and T-S2b measured both together.

## Evidence

- Before: ~1.6 stream copies and ~5 KB per draw (~2 GB/s of memcpy for the recorder).
- T-S2b, with the HZB remap and no diagnostics: heavy-view panning ~185 FPS, 1% ~150, 0.1% ~125. The user: the best
  so far (commit `57dc5c4`). T-W3d later used T-S2b as the reference.
- Deck: on in the preset (`perf_small_buffers=1`). No Deck A/B of S2 alone.
- Counters: "Small read-only buffers/s: bound from the arena, uploaded once, stream copies, found dynamic" on
  the Uploads line (`GOW3_STREAM_CLEAN` set).

## History and pitfalls

- Not T-S2 in plan-stage-b-split (small host copies to the copy threads, pool-small-copies), and not the S2 streaming
  test of plan-frame-pacing.
- The `stream_class.clear()` at 262,144 entries in the first version ran on stage B about once a second while
  panning. Any per-address table here must stay fixed-size.
- Built after T-HZ4f-h showed slow frames cost more per draw. The study expected ~0.05-0.1 us per packet.
