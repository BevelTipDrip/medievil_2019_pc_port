## What it does

With `GOW3_ARENA_HOST_VISIBLE` (read at start), `HostVisibleArenaType` picks a `DEVICE_LOCAL|HOST_VISIBLE|
HOST_COHERENT` type for the arena's residency chunks (`1`: cached preferred, `2`: uncached), and `ResidencyPool`
maps every chunk. `ArenaMappings` keeps each block's host address. When `DirectWriteBlocked` allows it, buffer
uploads (`UploadDirect`, C1) and precise CPU writes (`ProcessCpuWritesLocked`, C2) then copy into the mapping
instead of staging + `vkCmdCopyBuffer`. That removes the copy command, its barrier and any pass end. With no
suitable type, or a first chunk that cannot be mapped, U2 stays off.

## Invariants

- Every GPU use of the arena must be noted: `ObtainBuffer` calls `NoteArenaUse` after the sync, staged copies
  note their destination, and BDA reads call `NoteDmaUse`, which blocks all direct writes until the GPU passes it.
  A new arena user that skips this can have a direct write race it (wrong vertices, flicker). The live bit
  isolates this class of bug.
- A write may go direct only if the newest tick over its pages (4 KiB / 64 KiB / 1 MiB tables) and `dma_use_tick`
  is 0 (never used) or `< CurrentTick()` and `IsFree` (`DirectWriteBlocked`'s `in_flight`). The open command
  buffer's tick is never done, so a recorded but unsubmitted draw blocks the write. Addresses past 2^40 count as
  in use, and every block must be mapped (`ArenaMappings::Get`).
- Only a caller in order with the queued draws may write direct (`Scheduler::DrawRecorderQuiet`: stage B, or stage
  A with stage B empty). A direct write records nothing, so it gets no `SyncWithDrawRecorder`.
- WAW: with the arena mapped, every submission ends with a device-write -> host barrier (`SetHostAccessBarrier`,
  set at start whatever the toggle). C2 always writes GPU-written bytes, so it relies on this barrier.
- Host -> device visibility: direct writes run on the copy threads / caller batch and finish before
  `vkQueueSubmit` (`WaitHostCopies`). The type must stay `HOST_COHERENT`.
- Ticks are noted whenever `arena_mappings` exists, toggle on or off, so switching it on live is safe.

## Interactions

- Needs `ResidencyPool` (driver-memory-off-stage-b) for mapped chunks. With `GOW3_RESIDENCY_CHUNK_MB=0` each
  `EnsureResident` allocation is mapped instead.
- Defaults: `1` on Linux integrated GPUs (`instance.IsIntegrated()`), `0` elsewhere. The Deck preset's
  `DECK_SWITCHES` sets `GOW3_ARENA_HOST_VISIBLE=0` (setdefault), so the Deck default is off, but a Linux iGPU
  without the preset runs it on.
- S2 and every other arena binding add `NoteArenaUse` walks (3-4 per draw). Toggle word 2 bit 8 only gates the
  writes. The bookkeeping and the barrier stay on until `GOW3_ARENA_HOST_VISIBLE=0`.
- U5 (guest memory as GPU memory, not built) was the larger version of this idea.

## Evidence

- deck-u2-ab-1 (`ab4861a`, one launch, bit 8 every 30 s): memory type 3 (heap 1, 6144 MiB); 4.9 of 5 uploads a
  frame direct (~3.15 MB), 2 of ~92 pass ends saved; **FPS 62-63 both ways**, stage B ~80.7% both. The plan's
  verdict: "correct, no gain". The culling report from the next run (objects missing at distance) went with the
  HZB hidden count and had no experimental switch on. It is not tied to U2.
- Patch audit (#64): the A/B could not see U2's cost because the use-tick walk stays on in both states (estimate
  0-0.3 us a draw [inferred]). Every Deck run since had the key at 0. Never measured on Windows (ReBAR `1` untested).

## History and pitfalls

- Baseline trap (audit): a Deck launch without `GOW3_ARENA_HOST_VISIBLE=0` mixes U2's bookkeeping into "the new
  baseline". The preset now pins it to 0. The audit's planned clean A/B (key at 0 vs default) is still open.
- Status is arguably mixed: kept in the build, off on both measured platforms, on only for other Linux iGPUs. If
  that A/B shows a cost, change the Linux iGPU default to 0.
