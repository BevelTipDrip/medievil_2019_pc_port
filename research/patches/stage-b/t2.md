## What it does

Two kinds of texture binds that always took `BindTextures`' slow path use the texture-set memo when
`GOW3_TEXSET_WIDE=1` (`TextureSetWideWanted`, read once): stages with 17-32 images go to a table of their own
(`WideTextureSet`, 1,024 slots, two-way unless `GOW3_TEXSET_TWO_WAY=0`, the legacy layout with 32 entries, ~3 MB made on first use), and stages of
draws without a prepared draw compute their T# hashes at the bind (`ImageDescHash(image.GetSharp(stage), image)`)
instead of taking them from a draw-preparation worker. Lookup, validation, keep and drop are the generic
`BindTexturesFromSetIn` path every memoized set takes. `35f3930` keeps dispatches (`SwStage::Compute`) on the slow
path; indirect draws (never prepared) stay in.

## Invariants

- A hit must replay a set the slow path resolved for the same `Shader::Info*` (the key is seeded with `&stage`) and
  the same T# hashes. The bind-time hashes must come from exactly the sharps the slow path reads
  (`image.GetSharp(stage)` on stage B's registers); hashing anything else would let a hit bind stale images.
- Wide and unprepared sets get every check other memoized sets get (registry generation or region stamps, scene
  generation, backing, rebind, target, up-to-date, proxy, upscaler redirect). A check added inside
  `BindTexturesFromSetIn` covers every table; one added for a single table type would not.
- `count > (wide ? WideTextureSet::MaxImages : TextureSet::MaxImages)` and the written / mip-fallback image rule in
  `BindTexturesFromSet` still send those stages to the slow path.
- `texture_set_resolved` is a member array now: a slow-path call with a set slot must reset its images' entries
  (`std::fill_n` before the image loop) before writing them, and calls without a slot must not read it. The texture
  helper (`on_helper`) never gets a slot, so it never touches the array. This member array is used with T2 off
  too (it replaced the zeroed local array for every caller); a helper that ever gets a slot would race stage B on it.
- With `GOW3_TEXSET_WIDE` unset, or second toggle word bit 262144 set, every condition and table is as before
  (`TextureSetWide()` false); only the `texture_set_resolved` change above is unconditional.
- The wide table's lookups stay out of the "Texture-set memo per frame" counters (`Table::stat < 0`) and its keeps /
  drops are not counted there either; read them on the "Stage B cuts per frame" line.

## Interactions

- Builds on lineage-texture-set-memo and texset-region-stamps (validity). 1-16 image sets keep the compact table
  (texset-compact) or the legacy one (second word 2048); the wide table is always the legacy layout.
- T1 (stages without images), T2, R1-region-index and R2-residency-bitmap are one round and are switched off together
  by second word 983040 in the Deck runs.
- In DECK_SWITCHES (deck-preset), hence `default_deck: on`; not a Windows default. own-target-texsets stay out.

## Evidence

- Cuts redo (2026-11-07, draw preparation alive): R1/R2/T1/T2 off (983040) +3.8 points of a core at the 60 cap (stage B 50 -> 53%), +0.17 W CPU; uncapped 82.8 -> 81.7 FPS, presents > 15 ms 54 -> 89 a minute, worst 20.4 ms. Launch 15's +14.6 was inflated: with no prepared draws every draw took T2's path.
- Deck, `deck-perdraw-1.log` (AppImage `c71e87c`), all four cuts on vs off (`0 0` / `0 983040`): 78.8 vs 78.2 FPS,
  stage B busy 86.7 vs 92.6% (~0.75 ms a frame); T2 counters "46 + 175 sets at 100% hits" (over-16 / unprepared).
  Single bits off: 78.7-79.0 FPS, within noise.
- Launch 15 (Deck, uncapped, GPU-bound): R1/R2/T1/T2 off 77.6 FPS vs 78.3 all on; stage B 81.2 vs 76.0%; at the 60
  cap the four off cost +14.6 points of a core, +0.00-0.03 W CPU.
- The picture check the impl doc asks for while toggling `0 262144` is not recorded: not verified in game on its own.

## History and pitfalls

- The first version let compute stages in (no prepared draw); `35f3930` restricted it to draws (~34 dispatch binds a
  heavy Deck frame at ~1.6 us, not worth widening what T2 changes).
- Opt-in because it memoizes more kinds of passes (multi-texture post / lighting, the GPU-particle sim). A visual bug
  seen only with the Deck preset: `0 262144` in the toggle file is the live check.
