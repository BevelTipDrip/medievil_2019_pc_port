## What it does

Each GPU thread's 8-entry region cache (`region_cache`, used by `runtime_memory_clamp` / `_region` / `_is_mapped`)
was valid for one table-wide generation, bumped at every exclusive lock: UE4's ~6,000 pool commits a second emptied
it. Now 65,536 counters (`region_buckets`, one per 16 MiB of guest address space) are bumped by `region_changed`
wherever a mapping in the bucket changes; an entry holds `region_stamp` (sum of its buckets) and stays valid while the
sum is unchanged. L1's buckets plus one rule: `host_map` (Windows), `host_unmap` and `host_keep_view` bump the range
**before** the host mapping changes, so `cached_region` may answer even while a writer holds the lock.

## Invariants

- Any change that unmaps a range or turns it reserved must bump its buckets before the host call. Today: Windows
  `host_map`, both `host_unmap`s, `host_keep_view`, and the table edits (`vma_insert`, `vma_erase`, `split_at`).
  Linux `host_map` does not bump: safe only because every Linux path that removes a mapping goes through `host_unmap`
  (`unmap_locked`) or edits the table first (D4's `record_mapped` before `host_map_unlocked`); reservations over
  mapped memory are refused (`reserve_range` checks overlaps). A Linux `place` over a still-mapped range (MAP_FIXED
  direct / flexible map) remaps before the table edit bumps: the cached "mapped" stays true there, only the pages
  differ, and phys readers (A1) check `table_generation`. Breaking the rule lets a GPU thread use a cached "mapped"
  answer for memory that is gone (a fault on the guest mapping).
- Protection is not part of the cached answer: `host_protect` (guest `mprotect`, GPU page protection) needs no bump.
- Counters only grow, so a stamp can only match if none of its buckets changed. `region_stamp` returns 0 for a
  region spanning more than 64 buckets (1 GiB): such regions are never served from the cache.
- The bucket index is `>>24` modulo 65,536, which covers 1 TiB: the PS4 user range ends below 1 TiB (`USER_MAX`), so
  buckets do not alias [inferred from the constants].
- `cache_region` fills only under the read lock and only with an even generation; with `GOW3_REGION_BUCKETS=0` the
  old rule returns (no cached answer while the generation is odd).
- `GOW3_REGION_BUCKETS` is read once (static): a restart is needed; it is not live in the menu.

## Interactions

- L1-region-buckets: the reverted first version (no answers during writes); this re-applies it with the bump rule.
- lockfree-region-reads: same launcher switch, `perf_lockfree_memory=0` sets `GOW3_OPTIMISTIC_CLAMP=0` and
  `GOW3_REGION_BUCKETS=0`; the in-game menu switches only the lock-free part live.
- R1-region-index and A1 check their entries by these stamps; `region_index_wanted` is off without buckets.
- D4 and M1 / decommit-keep-access rely on the bump-before-host-change rule (see Invariants).
- First toggle word bit 1 turns every region cache off (clamp, region, is_mapped).

## Evidence

- T-L2 (stage-b-split 2026-10-19, build `03c363b`, `-Samples`, heavy view panning): stage B's lock waits in
  `ResolveVertexBuffers` -> `runtime_memory_clamp` ~2.4% (T-P3, the 2026-10-19 stage B profile: 4.7%); heavy view
  130-133 FPS, p99 8.5-9.2 ms, stddev 0.33-0.55 ms (T-O1: 126-135 FPS, p99 8.4-9.2). The doc: "L2 kept (half the lock
  waits, no change in FPS visible)". Not checked by the user in game on its own.
