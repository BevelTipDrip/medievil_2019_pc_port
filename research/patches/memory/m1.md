## What it does

A Windows pool decommit (`pool_decommit_impl` with `pool_keep_views()`) keeps the section view: its pages become
`POOL_KEPT` (`pool_give_locked`), the GPU unmap hook is queued, `host_keep_view` makes it no-access (or keeps its
access, decommit-keep-access) and the table entry becomes reserved. A commit at that address asks the view's physical
address (`host_view_phys`), takes those pages back (`pool_take_at_locked`), and `host_map_impl` only changes the
protection (`host_view_reusable`): no view unmapped or mapped. M1b: `pool_take_locked` hands out `POOL_FREE` pages
first and `POOL_KEPT` ones (second loop) only when no free page is left.

## Invariants

- `host_view_reusable` reuses a view only when one mapped region covers the whole range at exactly the wanted
  physical offset; anything else goes through `carve_host` (unmaps the kept view), or wrong pages get mapped.
- `pool_take_at_locked` takes `POOL_FREE` or `POOL_KEPT` pages, never `POOL_TAKEN` (no page mapped twice live).
- `POOL_KEPT` counts as used for `free_hint` (R3) and for the first loop of `pool_take_locked`; handing kept pages
  out early brings back the kept-view unmaps (8-37 ms kernel stalls with ~13,000 views, T-M1).
- A keeping decommit still queues `HOOK_UNMAP` and bumps the range's buckets (`host_keep_view` calls
  `region_changed`): the GPU side must forget the range although the view stays (L2).
- `pool_keep_views()` reads the toggle per call (bit 31 live). Flipped off, kept pages stay `POOL_KEPT` (second loop
  only) and the next commit at a kept view's address unmaps it through `carve_host` (phys no longer matches).
- Data: a recommit at the same address sees its own bytes (as on the PS4). UE4 relies on it (the Mausoleum bug on
  Linux, pool-kept-pages). **Open:** the second loop of `pool_take_locked`, and `pool_take_at_locked` on a stale kept
  view, hand kept pages to another owner un-zeroed (the Windows half of the Mausoleum leak; reached sooner with small
  pools, e.g. the Deck preset on the PC). Fix pending for `lab`: zero there (`host_discard` is a memset on Windows).

## Interactions

- pool-kept-pages: the Linux equivalent (no views); `pool_keep_views()` returns 0 off Windows. decommit-keep-access
  lives inside `host_keep_view`, so it acts only while M1 is on.
- narrow-image-stages: shares toggle bit 31 (`NarrowImageStages`); writing 2147483648 switches both off.
- R3: the kept state was added to the hinted search; the second loop scans from page 0 without a hint.
- lockfree-region-reads / A1: Windows `CopySparseSerial` copies straight from the guest mapping after an unlocked
  lookup (the `runtime_memory_copy_backing` stub says "kept views"). M1 alone does not make a racing copy safe: the
  kept view is `PAGE_NOACCESS` then, as faulting as the old unmapped hole. Only with decommit-keep-access (default)
  does a copy that raced a decommit read stale bytes instead [inferred from the code, never tested].
- D4: Windows keeps every host call under the table lock because the host views table (`regions`) is shared.

## Evidence

- Episode capture (build `5cd037e`, `heavy-episode-1.etl`): a System worker at one core, 78% `MiViewMayContainPage`,
  6% `MiTrimSection`; `RenderThread 1` blocked on `WrPushLock` 200-300 ms a second (RAM 41 GB free).
- T-H1 (build `2618b9c`): per 5 s ~60,000 host maps, ~30,000 unmaps, ~30,000 protects; views 4,734 at boot ->
  ~14,900; in an episode the same 64 KiB calls take 1-17 ms each (`effect-2.etl`: the same System-worker signature).
- T-M1 (`40a416a`): unmaps 0 in every window, kept ~= reused (18,900 / 18,900 per 5 s), views level at ~13,400, **no
  2-5 s episodes**; still ~50 reuse misses per 5 s, each a map unmapping a kept view (8-37 ms), a hitch frame.
- T-M1b (`3c5704e`): views ~3,400, 52 kept-view unmaps in the whole run, 2 slow host calls (max 2.6 ms). The user:
  the repeatable panning hitch is still there, no prolonged bursts any more (reported in the doc, not quoted).

## History and pitfalls

- **Windows leak fixed `8d4607e` (2026-11-07, LANDMINES item 9; built, not run):** `pool_owner` now exists on Windows; a
  decommit records the address whose bytes a page holds; `pool_take_locked` takers zero owned pages (the second
  loop handed kept views' pages out with their bytes); `pool_take_at_locked` takes back only the view's own or
  never-owned pages; a failed commit discards. Frame-stats line "Guest pool (window): kept-view pages taken back,
  another address's pages zeroed". Windows has no runtime-test target, so it is untested until a PC run.
- The T-M1b hitches left were streaming and game-side frames, not host calls (followed up by C2 / C3).
- "T-M1" names three tests (frame-pacing 2026-10-18 = this one; the 2026-10-26 movie suspend; stage-b-split's table
  stats). plan-linux-deck.md's "L2: keep pool views on Linux" is this idea for Linux, never built.
